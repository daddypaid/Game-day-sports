# GameDay Buyer Diligence Checklist

## Technical

- [ ] Record the accepted repository commit and verify every included file against `FINAL-TRANSFER-MANIFEST.md`.
- [ ] Confirm Pages deployment, V5 Demo, Buyer Walkthrough, sportsbook, casino, Architecture, Buyer Readiness, Admin Takeover and Transfer Audit.
- [ ] Run Final Sale Readiness Check and Transferability Check.
- [ ] Inventory the separately delivered Supabase schema/migrations, RLS policies, database functions, Edge Functions and scheduled jobs.
- [ ] Reproduce the TEST MODE environment under buyer-controlled GitHub and Supabase accounts.
- [ ] Rotate/recreate every secret; confirm no privileged credential is browser-exposed.
- [ ] Run authenticated test-wallet, wager, settlement and casino acceptance tests.
- [ ] Independently assess security, availability, backup/recovery and accessibility.

## Operational

- [ ] Identify buyer owners for hosting, monitoring, support, incident response, sports-data operations and vendor billing.
- [ ] Confirm domain/DNS, repository and Supabase takeover steps and seller-access revocation.
- [ ] Document recurring costs, quotas, rate limits, support terms and failure procedures for each service.
- [ ] Keep TEST MODE enabled through technical acceptance.

## Intellectual property

- [ ] Obtain a signed asset schedule covering source, branding, domain, documentation and each artwork/media file.
- [ ] Verify authorship, contractor assignments and chain of title.
- [ ] Review open-source licenses and attribution obligations.
- [ ] Exclude or separately license third-party marks, league/team branding, athlete likenesses, fonts, stock assets and restricted content.

## Third-party services and data providers

- [ ] Confirm whether each account may be assigned; otherwise create buyer-owned replacements.
- [ ] Execute buyer-owned sports-data agreements and verify display, caching, redistribution and commercial-use rights.
- [ ] Confirm GitHub, Supabase, domain, monitoring, messaging, payment and other vendor terms and costs.
- [ ] Do not infer rights from credentials, repository presence or prior technical access.

## TEST MODE and regulated-operation limitations

- [ ] Acknowledge that the package provides test credits only and no real-money deposits, withdrawals or wagers.
- [ ] Acknowledge that no gambling license or real-money authorization is included.
- [ ] Acknowledge that production KYC/AML, sanctions screening, age/identity verification, geolocation, responsible-gaming controls, gaming-approved payments, fraud/risk controls and regulatory reporting are not included.
- [ ] Obtain independent legal and regulatory advice for every intended jurisdiction before real-money use.
- [ ] Do not enable real-money operation until all legal, compliance, data-rights, security and operational requirements are independently completed.

## Closing evidence

- [ ] Signed purchase agreement and final asset/exclusion schedule.
- [ ] Final repository commit and exported archive hash.
- [ ] Backend-delivery inventory and migration acceptance record.
- [ ] Credential-rotation and seller-access-removal record.
- [ ] Passing buyer-controlled TEST MODE acceptance record.
